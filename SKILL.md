# Wearables Tech Frontiers (wtf)

Curated digest of wearable devices and sports-health algorithms for a technical
audience (算法 / 产品技术 lead). This skill is a **compressor + safety net**, not
an editor. It reads a central GitHub feed generated by GitHub Actions, then
remixes that feed into a dense digest with Top 3 scarcity scoring.

## Boundaries

- **No scheduled user push.** This is pull-only. The central feed is scheduled; user digests are on demand.
- **No ad-hoc topic search.** `/wtf` has no arguments beyond natural-language config/window overrides.
- **No runtime Tavily/WebSearch.** Vendor fallback is already included in the central feed.
- **No runtime Chinese WebFetch in v1.** Chinese sources are manual-check hints until central extraction is added.
- **No X/Twitter coverage.** Use `follow-builders` in parallel if needed.
- **No telemetry.** Healthcheck output is printed only to the user.

## Resource model

- **Central feed:** `feed-wearables.json` from `https://raw.githubusercontent.com/waylongo/wearables-tech-frontiers/main`.
- **Remote prompts/catalog:** loaded from the same GitHub raw base when available.
- **Local fallback:** shipped `config/sources.json` and `prompts/*.md`.
- **User override:** `~/.wtf/sources.json` or `~/.wtf/prompts/<file>.md`; if user sources exist, `prepare-digest.js` uses local RSS fallback so private sources are included.

## First Run — Onboarding

Check if `~/.wtf/config.json` exists with `onboardingComplete: true`.
If NOT, run this flow. Keep it minimal.

### Step 1: Introduce coverage

Tell the user:

"我是 wearables-tech-frontiers（简称 wtf）—— 给可穿戴算法 / 产品技术 lead 用的周报式情报。

**我覆盖什么：**
- **学术 / 预印本** — arXiv、medRxiv、bioRxiv、npj Digital Medicine、Nature BME、JMIR mHealth、Lancet Digital Health、PLOS Digital Health、IEEE JBHI、Frontiers Digital Health
- **厂商研究** — Apple ML Research / Google Research / DeepMind
- **行业媒体** — MobiHealthNews / 9to5Mac / 9to5Google / The Verge（带关键词过滤）
- **厂商站点兜底** — Samsung / Huawei / Oura / WHOOP / Garmin / Withings / Dexcom / Zepp（由中心 GitHub Actions 调 Tavily，不在本地运行）

**我不覆盖：** X/Twitter · PubMed 私有关键词 feed · 中文站点自动抓取（首版仅给手动巡检提示）

**我怎么工作：** 你输入 `/wtf`，我读取中心 feed，按你的窗口和语言偏好生成 digest。不推送、不定时、不在你睡觉时干活。"

### Step 2: Ask 3 questions

1. "默认看过去多少天？" → `windowDays`（常见：1 / 7 / 14）
2. "输出语言？" → `language`（zh / en / bilingual）
3. "默认覆盖哪些层？" → `categories`（全部 / 只学术+厂商研究 / 全部减学术）

### Step 3: Save config

```bash
mkdir -p ~/.wtf
cat > ~/.wtf/config.json << 'CFGEOF'
{
  "windowDays": <1|7|14>,
  "language": "<zh|en|bilingual>",
  "categories": [<academic, vendor_research, industry_news>],
  "onboardingComplete": true
}
CFGEOF
```

### Step 4: Run first digest

Run the Content Delivery workflow immediately.

## Content Delivery — Digest Run

Triggered when the user invokes `/wtf` or during first-run onboarding.

### Step 1: Run prepare-digest.js

```bash
node "${CLAUDE_SKILL_DIR:-$PWD}/scripts/prepare-digest.js"
```

Optional args from user phrasing:
- "看过去 N 天" → `--days=N`
- "只看学术" → `--category=academic`
- "跳过远程更新" → `--no-remote`

The script outputs:
- `items` + `groupedByCategory` — the only allowed content pool
- `monitorOnlyHints` — manual-check bookmark list
- `prompts` — remix rules
- `healthcheck` — source health, filter stats, feed source, Tavily center-run stats
- `scarcityTaxonomy` — Top 3 scoring rubric

### Step 2: Check volume

If `stats.keptItems == 0`:

"过去 [windowDays] 天所有 P1 源都没有符合过滤条件的内容。这通常是周末 + 低产出期。可以输入 `/wtf 看过去 14 天` 扩大窗口。"

Then stop.

### Step 3: Remix

Follow the prompts in the JSON:
- `prompts.digest_intro` — Top 3 rubric + structure + healthcheck footer
- `prompts.summarize_papers` — academic items
- `prompts.summarize_official` — vendor_research items
- `prompts.summarize_news` — industry_news and vendor_websearch items
- `prompts.translate` — apply when language is zh or bilingual

Top 3 selection is the single most important decision. Apply the 5-step flow in
`digest-intro.md` using `scarcityTaxonomy`. Never invent categories. Never pad
Top 3 if candidates score below threshold.

Mandatory healthcheck writebacks during remix:
- `healthcheck.top3_categories`
- `healthcheck.top3_scores`
- `healthcheck.top3_rejected_candidates`

### Step 4: Render monitor-only hints

Append:

```text
🏭 手动巡检提示（中心 feed 尚未覆盖的源）
```

List 8-12 URLs from `monitorOnlyHints`. Keep it short.

### Step 5: Apply language

- `en` — English only
- `zh` — Chinese only, keep technical abbreviations in English
- `bilingual` — Chinese summary first, English title/summary paired where useful

### Step 6: Healthcheck footer

Follow `prompts.digest_intro`. Use script-provided healthcheck fields plus the
Top 3 fields you populated. Always include Top 3 categories, scores, and near
misses.

### Absolute rules

- Only use `items` from the JSON. Never invent.
- Every bullet must carry its URL. No URL = drop.
- Do not refetch article URLs.
- Do not run Tavily/WebSearch/WebFetch during digest.
- Never editorialize. No "重磅", "颠覆", "震惊", "历史性突破".
- Top 3 category labels must match `scarcityTaxonomy.categories`.

## Configuration Handling

When the user says "换成每日" / "只看学术" / "默认改成 14 天" / "换双语":

1. Read `~/.wtf/config.json`
2. Apply the change
3. Write it back
4. Confirm in one line: "已改成 [diff]，下次 /wtf 生效。"

Supported changes:
- `windowDays`: 日报 / 周报 / 双周报 / 月报 → 1 / 7 / 14 / 30
- `language`: zh / en / bilingual
- `categories`: academic / vendor_research / industry_news

### One-time window vs persistent default

| 用户说 | 含义 | 实现 |
|---|---|---|
| "看过去 14 天" / "这次看双周报" | 仅本次覆盖 | `prepare-digest.js --days=14` |
| "默认改成双周报" / "以后都看 14 天" | 持久化默认 | 改 `~/.wtf/config.json` |

### Source customization

- "加一个源 [URL]" → append to `~/.wtf/sources.json`; this causes local RSS fallback so private sources are included.
- "显示当前所有源" → pretty-print merged public catalog + user catalog.

### Prompt customization

- "summary 再短一点" / "多关注临床" / "少用 emoji" → copy the relevant prompt to `~/.wtf/prompts/<name>.md` and edit it there.

## Debug

If the user says "这次 digest 有问题" / "dump JSON" / "debug", rerun:

```bash
node "${CLAUDE_SKILL_DIR:-$PWD}/scripts/prepare-digest.js"
```

Output the full JSON in a code block, with a brief note of feed source, failed
sources, Tavily center-run stats, and filter counts.
